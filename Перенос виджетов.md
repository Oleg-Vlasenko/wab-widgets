# Руководство по переносу пользовательских виджетов WAB

## Назначение

Необходимо перенести на новый сервер:

* Web AppBuilder пользовательские виджеты;
* PHP Proxy;
* Python Service;
* PostgreSQL/PostGIS.

После переноса все пользовательские виджеты должны работать без изменения функциональности.

---

# 1. Перенос пользовательских виджетов

## Размещение

Скопировать каталоги пользовательских виджетов:

```text
XOtgSearch
XOtgParcel
XOtgLine
XOtgRedLine
```

в каталог

```text
<Portal>\apps\webappviewer\widgets\
```

например

```text
E:\ArcGIS\Portal\apps\webappviewer\widgets\
```

---

## Регистрация виджетов

В ArcGIS Portal:

```
Ресурсы
→ Добавить
→ Приложение
→ Расширение приложения (AppBuilder)
```

В поле **URL описания** указать путь к `manifest.json` каждого виджета.

Например

```
https://<portal>/portal/apps/webappviewer/widgets/XOtgParcel/manifest.json
```

После регистрации виджет должен появиться во вкладке **Пользовательские**.

---

# 2. Размещение PHP Proxy

Разместить каталог

```
flask_proxy
```

на том же IIS/Web-сервере, где работает Portal.

Структура должна быть примерно следующей

```
Portal
│
├── apps
├── webappviewer
└── flask_proxy
      │
      ├── index.php
      └── broker.php
```

---

## Настройка

В файле

```
index.php
```

необходимо изменить адрес Python-сервиса.

Например

```php
http://<python_server>:5024/
```

если изменился IP-адрес или имя сервера.

---

## Проверка

В браузере открыть

```
https://<portal>/flask_proxy/index.php
```

Запрос должен успешно доходить до Python-сервиса.

---

# 3. Развертывание Python Service

Скопировать каталог Python-сервиса на сервер.

Создать виртуальное окружение.

Установить зависимости:

```
pip install -r requirements.txt
```

(если requirements отсутствует — установить используемые библиотеки вручную).

---

## Настройка

В конфигурации необходимо проверить:

* адрес PostgreSQL;
* имя базы данных;
* пользователя;
* пароль;
* порт Flask.

---

## Запуск

Запустить Flask как сервис Windows либо другим способом, принятым в инфраструктуре.

После запуска должны быть доступны HTTP endpoints:

```
/find_geom

/find_trs

/parcelgeom

/parcelgeoml

/render_poly

/rlupload
```

---

## Проверка

Открыть

```
http://<python_server>:5024/
```

и убедиться, что сервис отвечает.

---

# 4. PostgreSQL/PostGIS

Установить

* PostgreSQL
* PostGIS

Создать базу данных.

Импортировать структуру и данные.

Настроить пользователя, используемого Python-сервисом.

---

## Проверка

Убедиться, что Python успешно подключается к базе данных.

---

# 5. Проверка работоспособности

После завершения переноса проверить:

### XOtgSearch

* поиск по адресу;
* поиск по заказчику;
* открытие отчета.

---

### XOtgParcel

* рисование полигона;
* открытие отчета.

---

### XOtgLine

* поиск инженерной сети;
* анализ нарисованной линии.

---

### XOtgRedLine

* загрузка полигона;
* успешное выполнение запроса.

---

# 6. Что потребуется изменить после переноса

При изменении адресов серверов необходимо обновить:

| Компонент     | Что изменить                                              |
| ------------- | --------------------------------------------------------- |
| Widget.js     | URL Python Service (если используется прямой вызов Flask) |
| index.php     | URL Python Service                                        |
| config.py     | параметры подключения к PostgreSQL                        |
| manifest.json | только при переименовании виджета                         |

---

# Архитектура системы

```
Browser
    │
    ▼
ArcGIS Portal / Web AppBuilder
    │
    ├── Custom Widgets
    │
    ├── PHP Proxy (index.php)
    │
    ▼
Python Service (Flask)
    │
    ▼
PostgreSQL + PostGIS
```

---

## Примечание

В текущей реализации используются **два способа обращения к Python-сервису**:

1. **Через PHP Proxy** (`index.php`) — для операций поиска (`find_geom`, `find_trs`).
2. **Напрямую по HTTP** — для формирования отчетов и загрузки данных (`parcelgeom`, `parcelgeoml`, `rlupload`).

При переносе системы необходимо проверить корректность всех URL-адресов, так как часть из них задана непосредственно в коде пользовательских виджетов (`Widget.js`). Это наиболее частая причина неработоспособности после миграции.
