# Руководство разработчика

## 1. Назначение системы

Система предназначена для расширения ArcGIS Web AppBuilder пользовательскими виджетами пространственного анализа.

Архитектура построена по схеме

```text
Web AppBuilder
       │
       ├── Custom Widgets
       │
       ├── PHP Proxy
       │
       ▼
Python (Flask)
       │
       ▼
PostgreSQL + PostGIS
```

# 3. Назначение виджетов

| Виджет      | Назначение                           |
| ----------- | ------------------------------------ |
| XOtgSearch  | поиск объектов по адресу и заказчику |
| XOtgParcel  | анализ земельного участка            |
| XOtgLine    | анализ инженерных сетей              |
| XOtgRedLine | загрузка красных линий               |

---

# 4. Кто за что отвечает

## Widget

Отвечает только за интерфейс пользователя.

* кнопки
* Draw Toolbar
* отображение Graphics
* формирование GeoJSON
* вызов HTTP

Никакой пространственной логики здесь нет.

---

## PHP Proxy

Используется только для поиска.

```
find_geom

find_trs
```

PHP только пересылает запрос во Flask.

---

## Flask

Главная бизнес-логика проекта.

Отвечает за

* пространственные запросы;
* формирование отчетов;
* выборку объектов;
* анализ геометрии.

---

## PostGIS

Хранение пространственных данных.

Все пространственные вычисления выполняются SQL.

# 11. Добавление нового анализа

Практически всегда изменения затрагивают четыре места.

```
1. Widget.js

↓

2. routes.py

↓

3. service.py

↓

4. SQL
```

Эта последовательность одинакова почти для всех новых функций.

---

# 12. Полезно помнить

* **Widget.js** — только пользовательский интерфейс и вызовы сервисов.
* **PHP** — только прокси для части REST-запросов.
* **Flask** — центр всей бизнес-логики.
* **PostGIS** — источник всех пространственных данных и вычислений.
* Все четыре виджета используют одну и ту же архитектуру; различаются только конечные REST-эндпоинты и пользовательские сценарии.

## Я бы добавил ещё одну страницу, которая через полгода окажется самой полезной

### **"Карта проекта"**

```text
Portal
│
├── widgets
│    ├── XOtgSearch
│    ├── XOtgParcel
│    ├── XOtgLine
│    └── XOtgRedLine
│
├── flask_proxy
│    ├── index.php
│    └── broker.php
│
└── Flask
     ├── app.py
     ├── routes.py
     ├── service.py
     ├── config.py
     └── templates/
          │
          ▼
     PostgreSQL/PostGIS
```

Именно такую схему я обычно делаю для подобных проектов. Когда возвращаешься к системе спустя полгода-год, она позволяет буквально за пару минут вспомнить, **где находится нужный код, какой компонент за что отвечает и в какой файл идти для внесения изменений**. Это экономит гораздо больше времени, чем подробное описание каждого метода или класса.
